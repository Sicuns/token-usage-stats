# token-usage-stats

一份脚本，统计本机所有 AI 编码工具的 token 用量、真实积分与缓存命中率。

零第三方依赖（Python 3.8+ 标准库）、不联网、数据不出本机。双击即可看，也能被 AI Agent 直接调用。

## 为什么需要它

官方客户端只给你一个"本月已用多少"的数字，不告诉你：

- 昨天和今天各用了多少，哪天的量突然翻倍
- 哪个模型最烧钱 —— **token 多不等于花得多**。按同一口径折算，glm-5.3 每百万 token 的积分消耗约为 deepseek-v4.1-flash 的 38 倍，用它省下的那点 token 抵不过单价差
- 缓存命中率多少 —— 命中部分单价差 50 倍，这是账单高低的关键
- 高峰/非高峰用量各占多少 —— 非高峰 5 折，作息直接决定花费

这些数据其实都躺在本地日志里，只是没人替你算。

## 快速开始

```bash
git clone https://github.com/Sicuns/token-usage-stats.git
cd token-usage-stats

python scripts/usage_stats.py            # 交互菜单
python scripts/usage_stats.py --scan     # 先跑这个，看本机哪些工具能统计
```

## 常用命令

| 目的 | 命令 |
|---|---|
| 近 7 日 / 30 日汇总 | `--days 7` / `--days 30` |
| 今日各模型分布 | `--date today` |
| 指定某天 | `--date 2025-03-13` |
| 按平台对比 | `--by-source` |
| 数据源诊断 | `--scan` |
| 导出 JSON | `--json` |
| 只看某几个平台 | `--only workbuddy,codex` |
| 表后循环下钻 | `--interactive`（回车看今日，x 退出） |
| 忽略时间预筛、扫全部历史 | `--full` |

不带参数直接运行且当前是终端时，会进交互菜单。

## 支持的平台

| 平台 | 默认路径 | 解析方式 |
|---|---|---|
| WorkBuddy | `~/.workbuddy/projects` | 精确解析，可拿到**真实扣费积分** |
| Codex CLI | `~/.codex/sessions` | 精确解析，按增量累加 |
| Claude Code | `~/.claude/projects` | 通用解析 |
| QoderWork / Qoder | `~/.qoderworkcn/projects`、`~/.qoder/projects` | 通用解析 |
| Gemini CLI | `~/.gemini/tmp` | 通用解析 |
| Qwen Code | `~/.qwen/tmp` | 通用解析 |
| OpenCode / Crush / Goose / Aider | 见脚本 `SOURCES` | 通用解析 |

**通用解析器**不认工具名，只在日志 JSON 里寻找形似 usage 的对象，自动识别 Anthropic 系（`input_tokens` 不含缓存）与 OpenAI 系（`prompt_tokens` 含缓存）两种语义，并用 `message.id` 去重，避免流式重写导致重复计数。

所以新增一个平台基本不用改代码：在该文件顶部的 `SOURCES` 里加一行 `id / name / path`，`kind` 填 `generic` 即可。

路径不同也可用配置文件覆盖（`~/.ai-usage-stats.json`）：

```json
{"paths": {"claude": "D:/backup/claude-projects", "codex": "E:/codex/sessions"}}
```

## 三个关键口径

### 1. 积分是服务端返回的**实扣值**，不能再打折

WorkBuddy 每条请求日志里有 `providerData.rawUsage.credit`，是本次调用实际扣掉的积分，字段覆盖率 100%。

用同一模型对比高峰 / 非高峰的**单位积分**（单价，与个人用量多少无关）：

| 模型 | 高峰(分/百万) | 非高峰(分/百万) | 比值 |
|---|---|---|---|
| deepseek-v4.1-flash | 2.05 | 1.04 | **0.51** |
| deepseek-v4-flash | 5.12 | 2.64 | **0.52** |
| glm-5.3 | 54.81 | 49.72 | 0.91 |

deepseek 系列正好是 5 折，说明服务端已经算过峰谷了。**再乘 0.5 会把花费算少一半。**

### 2. 峰谷只影响"金额估算"

周一至周五 09:00–12:00、14:00–18:00 为原价，其余时段（含周末）5 折，按 `--tz` 指定时区判定（默认 UTC+8）。

### 3. 金额列是统一基准，不是账单

按 deepseek-v4.1-flash 牌价折算（输入 2.0 / 输出 8.0 / 缓存命中 0.04 元每百万），目的是让不同平台、不同模型之间**可比**，不代表实际付费。实际花费看积分列。

## 设计取舍

- **两个精确解析器 + 一个通用解析器**。WorkBuddy 的积分字段和 Codex 的增量语义都值得专门适配；其余平台结构各异但本质相同，用通用提取比逐个硬编码更耐用。
- **按 mtime 预筛**。默认只读最近 `--days + 3` 天修改过的文件，7 日查询 1.5 秒完成；`--full` 可关掉。
- **中文按显示宽度对齐**。Python 的 `%s` 按字符数补齐，中文占两列，直接用会错位；这里用 `unicodedata.east_asian_width` 计算真实宽度。
- **不去猜不存在的用量**。目录存在但日志里没有 token 字段时，如实显示"无用量记录"，不会估一个假数字。

## 作为 WorkBuddy Skill 使用

把仓库放进 `~/.workbuddy/skills/token-usage-stats/`（含 `SKILL.md`），之后直接问 AI "我今天用了多少 token"，它就会调这个脚本并解读结果。

## 常见问题

**Q：为什么某个平台显示"无用量记录"？**
该工具的日志里没有 token 字段。比如 QoderWork 的会话记录只有消息内容，用量只在客户端界面上显示，落不了盘，这种情况无法统计——不是脚本的问题。

**Q：数字一直在涨？**
当前对话也在实时写日志，同一天多次运行会小幅变化，正常。

**Q：能统计 API key 的消费吗？**
不能。这里只读本地工具日志，不访问任何服务端账单接口。

## 维护说明

个人自用工具整理而成，**不设路线图、不承诺响应时间**，issue 和 PR 可能不会及时回。

但这个项目的结构决定了它不太需要维护：

- 纯标准库，没有第三方依赖会过期，也没有构建产物要更新
- 没有 CI、没有版本号，clone 下来直接跑
- 新增平台只改 `SOURCES` 一行，通用解析器不绑定任何工具的具体版本

想加平台直接提 PR：改一处 `SOURCES`，再在「支持的平台」表里补一行，看到就会合。
